静态站点构建成功，不等于上线准备完成。

构建只证明代码可以生成页面；上线检查要确认页面在真实域名、真实子路径、真实内容和真实服务条件下仍然可用。下面十二项适合放进发布前清单，每次大改后重新过一遍。

## 1. 部署路径与资源前缀

GitHub Pages 项目页通常部署在：

```text
https://<username>.github.io/<repository>/
```

如果站点仍按根路径 `/` 生成资源，CSS、脚本、图片和搜索索引都可能 404。

Astro 可以使用环境变量控制 `base`：

```js
base: process.env.BASE_PATH || "/",
```

部署工作流中再设置：

```yaml
env:
  BASE_PATH: /Firefly
```

本地开发仍使用 `/`，CI 构建使用项目页子路径。

## 2. 站点绝对地址

`site` 和 `base` 是两件事。站点地址通常只填 origin：

```ts
site_url: "https://greenfinchgreen-gif.github.io"
```

子路径交给 `base`。这样 sitemap、canonical 和社交分享图不会重复拼接路径。

## 3. 首页与 404

- 首页能够正常加载。
- Logo 点击后回到正确首页。
- 刷新文章页不会 404。
- 手动访问不存在的路由会进入站点自己的 404。
- 404 页的“返回首页”会带上部署子路径。

## 4. 导航入口

逐个点击导航项，确认：

- 页面开关关闭后，入口自动隐藏。
- 外部链接使用 HTTPS。
- 新窗口链接带有 `noopener`。
- 不出现模板作者的演示站、旧文档地址或没有内容的页面。

导航宁少勿多。缺少一个页面比展示一个坏入口更容易接受。

## 5. 模板内容清理

至少搜索并检查：

```text
示例
Demo
1970
example.com
模板
上游仓库地址
```

重点不是删除所有出现“模板”的句子，而是确认：

- 文章列表没有演示文章。
- 关于页不是模板安装说明。
- 项目页不是上游 README 的复制。
- 动态没有“测试动态”。
- 友链和打赏没有虚构人物。

## 6. Frontmatter 一致性

每篇文章至少检查：

```yaml
title: 标题
published: 2026-10-25
description: 摘要
image: ""
tags: [站点运营, Astro]
category: 网站运营
draft: false
```

确认日期格式可解析、分类拼写统一、标签没有重复同义项、系列顺序没有冲突。

## 7. 摘要与标题层级

- 列表摘要应能独立说明文章内容。
- 页面只保留一个一级标题，正文从二级标题开始。
- 标题层级连续，不为了字号直接跳到四级。
- 长文增加目录容易扫描的段落。

## 8. 图片与体积

- 封面图有明确来源和使用授权。
- 图片文件名可读，不使用随机下载名。
- 优先使用 WebP 或 AVIF。
- 为图片填写准确的替代文本。
- 删除没有被内容引用的模板图片。

图片是静态博客最常见的体积来源，也是最容易在迁移中产生坏链接的资源。

## 9. RSS、Sitemap 与搜索

构建完成后检查：

- `/rss.xml` 可访问。
- `/atom.xml` 可访问。
- `/sitemap-index.xml` 可访问。
- Pagefind 搜索索引已经生成。
- 搜索框在新域名和子路径下仍能加载索引。

## 10. 未配置的服务

评论、统计、打赏、音乐和第三方 API 都属于外部依赖。

没有后端地址、数据说明和审核规则时：

- 不展示评论框。
- 不展示示例收款码。
- 不加载有版权疑问的音乐。
- 不把密钥写进前端配置。

功能可用性应当由真实配置决定，而不是由示例数据撑起来。

## 11. 构建与类型检查

提交前至少执行：

```bash
pnpm check
pnpm type-check
pnpm build
git diff --check
```

它们分别覆盖 Astro 诊断、TypeScript、生产构建和补丁格式。构建通过后再检查生成目录中的入口页、404 和资源路径。

## 12. 回滚路径

上线前确认：

- 改动在 Git 中可审阅。
- 大范围删除前有可恢复备份。
- 部署失败时可以重新运行上一个成功版本。
- 不把 `dist`、缓存和本地密钥提交进仓库。

上线不是一次性的按钮操作，而是一套可回滚的发布动作。

## 发布后二十四小时

上线后观察首页、文章页、RSS 和搜索是否出现 404；检查浏览器控制台的资源错误；确认移动端导航与正文宽度正常。发现问题先记录具体 URL 和复现步骤，再做修复。

清单的价值不在形式完整，而在于把“我觉得应该没问题”换成可以逐项验证的事实。
